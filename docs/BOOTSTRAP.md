# EverStone Bootstrap Runbook

This guide walks you through deploying a fresh EverStone Hermes hub on your own
host. The architecture and design rationale are in
[`architecture.md`](architecture.md).

---

## 1. One-time host setup

Anywhere with Docker can run EverStone — a small VPS, a homelab box, or a
Raspberry Pi. The image bundles Caddy, CouchDB, Radicale, livesync-bridge,
Hermes, the access-control plugin and engraph; the only thing you need is
Docker.

```bash
# Install Docker (Debian/Ubuntu example — adapt for your distro)
curl -fsSL https://get.docker.com | sh

# Clone the repo
git clone https://github.com/<you>/everstone.git
cd everstone

# Build the image
docker build -t everstone:dev .
```

---

## 2. Write `config.yaml`

Copy the template below into `./config.yaml`. Every field is required — the
container validates against `config/schema.json` on first start and refuses to
launch if anything is missing.

```yaml
couchdb:
  # CouchDB admin used by LiveSync clients and the bridge.
  user: everstone
  password: CHANGE_ME            # long random string
  database: everstone            # vault DB name (must match obsidian.vault_name in LiveSync UI)

caldav:
  # Radicale HTTP Basic credentials. Used by Tasks.org / Apple Calendar.
  user: everstone
  password: CHANGE_ME

livesync:
  # Both passphrases are generated by Obsidian LiveSync's "Generate passphrase"
  # button. Keep them in a password manager — losing them = re-pairing every device.
  passphrase: CHANGE_ME
  obfuscate_passphrase: CHANGE_ME

obsidian:
  # The vault name Obsidian shows on the device. Must match the deeplinks
  # the agent writes to tasks (obsidian://open?vault=<this>&file=...).
  vault_name: everstone

instance:
  # Display name your bot uses for itself in messages.
  name: Jarvis

telegram:
  # Your Telegram numeric user id (NOT your @username). Get it from @userinfobot.
  owner_user_id: 123456789
  # BotFather → /newbot → token. Treat as a secret.
  bot_token: 1234567890:ABCdef...

```

> **Note:** The LLM model is NOT set in `config.yaml` — set it once after first
> boot with `just model <provider/model>` (see step 4 below).

Important defaults:

* The image only allows the user id listed in `telegram.owner_user_id` to
  interact with the bot. Everyone else is dropped silently. There is no
  group-id allowlist — group access is gated by `chat_type` instead.
* In a group chat the bot can only run the `everstone_tasks` MCP tool. DMs
  from the owner are unrestricted. To widen the group allowlist set the
  `EVERSTONE_GROUP_TOOLS` env var (see step 6).

---

## 3. Run the container

```bash
docker run -d \
    --name everstone \
    --restart unless-stopped \
    -p 80:80 \
    -v "$PWD/config.yaml:/opt/config.yaml:ro" \
    -v everstone-data:/opt/data \
    everstone:dev
```

The repo also ships a convenience wrapper: `./run_local.sh`.

Watch it come up:

```bash
docker logs -f everstone
# Wait until you see livesync-bridge log "all peers connected" or similar.
curl http://localhost/health   # → "OK"
```

## 4. First-run actions inside the container

### Set the LLM model and run provider auth

Run this once after first boot. It sets the model **and** runs the provider's
OAuth flow in one step:

```bash
just model openai-codex/gpt-5.5
```

For codex, `esadmin model` prints an OAuth URL — open it in a browser and paste
the redirect URL back at the prompt. For API-key providers (Anthropic, OpenAI
direct, OpenRouter, etc.) the command will prompt you for the key instead.

This replaces the old `esadmin auth hermes` command. The model and provider are
stored in the Hermes profile under `/opt/data/hermes` and survive container
rebuilds.

### Sanity-check supervision

```bash
docker exec everstone s6-rc -a list
# Should list: caddy couchdb radicale hermes livesync-bridge (plus the
# one-shot setup_* services).
```

## 5. Client setup

### Obsidian LiveSync

1. Install the **Self-hosted LiveSync** plugin in Obsidian.
2. Open *Settings → LiveSync → Setup Wizard → Use the copied setup URI*.
3. Generate a setup URI on the server:

   ```bash
   docker exec everstone /scripts/setupuri
   ```

   Copy the printed URI (starts with `obsidian://setuplivesync?...`), open it
   from inside Obsidian (or paste into the wizard), and the plugin will fill
   in the CouchDB URL (`http://<host>/db`), credentials and passphrases for
   you. Verify the vault name matches `obsidian.vault_name` from `config.yaml`.

### Tasks.org on Android

* *Settings → Synchronization → CalDAV → Add account*
* Server: `http://<host>/caldav/<caldav.user>/` — note the trailing slash.
* Username / password: the `caldav` block from `config.yaml`.
* Tasks.org will discover existing task lists (default: `inbox`) automatically.

### macOS Calendar / Reminders

* *System Settings → Internet Accounts → Add Other Account → CalDAV*
* Account type: *Manual*
* Server address: `<host>/caldav/<caldav.user>/`
* Username / password: same as above.

### Tailscale (recommended)

Don't expose port 80 to the public internet. Put the host on your tailnet and
reach it at `everstone.<tailnet>.ts.net`. All clients above accept that
hostname unchanged. **Never publish EverStone on the open internet** — the
HTTP endpoints are unauthenticated below the application level, and the bot's
only access control is its own allowlist.

## 6. Widening group access (optional)

By default the access-control hook lets group chats invoke only
`everstone_tasks`. If you want the bot to also handle, e.g., a reminders
tool in a group, set `EVERSTONE_GROUP_TOOLS` to a comma-separated allowlist
when you launch the container:

```bash
docker run … -e EVERSTONE_GROUP_TOOLS=everstone_tasks,reminders … everstone:dev
```

Leave Telegram **privacy mode ON** in BotFather (the default). The bot will
only see messages directed at it via mention or reply, which keeps group
chatter out of Hermes' context.

---

## 7. External lockdown check

The bot's allowlist is enforced at the Telegram gateway. Verify it before
trusting the bot in any shared space:

1. Ask a friend (anyone whose user id is not in `telegram.owner_user_id`) to
   DM your bot.
2. Tail Hermes' logs: `docker exec everstone sh -c 'tail -f /opt/data/hermes/log/*.log'`
3. You should see **no agent invocation** for their messages. The gateway
   drops them before the model is called.

Also confirm the access hook is wired in:

```bash
docker exec everstone python3 -c "from importlib.metadata import entry_points; \
print([ep.name for ep in entry_points(group='hermes_plugins')])"
# Expect: ['everstone_access_hook']
```

## 8. Backups

EverStone ships a one-shot backup script that tars CouchDB, the vault,
Radicale collections and the Hermes state directory into a single archive:

```bash
docker exec everstone /scripts/backup
docker cp everstone:/opt/data/backups/everstone-YYYY-MM-DDTHHMMSSZ.tar.gz ./
```

The script keeps the seven newest tarballs and prunes the rest. Wire it into
a host cron (`0 3 * * * docker exec everstone /scripts/backup`) and copy the
archives off-box to your storage of choice.

### Restore

```bash
docker rm -f everstone
docker volume rm everstone-data    # only if you want a clean slate
docker volume create everstone-data
docker run --rm \
    -v everstone-data:/opt/data \
    -v "$PWD/everstone-2026-06-04T030000Z.tar.gz:/backup.tar.gz:ro" \
    alpine sh -c 'cd /opt/data && tar -xzf /backup.tar.gz'

# Start the container as in step 3 — data will be repopulated from the tarball.
```

---

## 9. Updating

```bash
cd everstone
git pull
docker build -t everstone:dev .
docker rm -f everstone
docker run -d --name everstone --restart unless-stopped -p 80:80 \
    -v "$PWD/config.yaml:/opt/config.yaml:ro" \
    -v everstone-data:/opt/data \
    everstone:dev
```

Reusing the same `everstone-data` volume preserves CouchDB, the vault,
Radicale collections, Hermes state and previous backups across upgrades.

## Known limitations

### Telegram slash-command menu shows Hermes built-ins

When you open the bot in Telegram, the autocomplete menu (`/`) shows
~30 Hermes-internal slash commands (`/help`, `/new`, `/stop`, `/status`,
`/resume`, `/sessions`, `/model`, …). These come from Hermes itself and
its `set_my_commands` registration call cannot currently be disabled via
config — the call site in `gateway/platforms/telegram.py` is unconditional.

**Impact:** UX clutter only. The commands are still functional (type `/new`
in Telegram and a fresh session does start). EverStone's own `telegram.commands`
config value gets overwritten by Hermes a few seconds later at gateway boot.

**Workarounds (none deployed):**
- Upstream PR to add `messaging.telegram.publish_menu_commands` config
- Post-hermes-start oneshot that re-calls `setMyCommands` after Hermes registers
- Live with it

**Status:** Won't-fix for now. Revisit if upstream adds a knob or the menu
becomes a real friction point.
